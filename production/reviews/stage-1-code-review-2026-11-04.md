## Verdict

**Approved with fixes — 0 CRITICAL, 1 IMPORTANT, 3 ADVISORY, 2 NIT.** The stage is in strong shape: every swap the stories claim was actually made (no `loopsStopAll` callers remain outside audio.js), the never-crash fallbacks are real guarded code rather than decoration, the quantize step registers its extension and never rewrites the canonical GLBs, and the music lifecycle holds together across every phase path I could trace (boot, launch, warp, SKIP, death, REPLAY, restart-probe), with per-phase `loopsCount()` matching the sound spec's expected counts exactly. The one IMPORTANT defect is a silent high-score write drop with a factually false catch comment on a line the diff touched; the advisories are a render-time bloom failure mode the construction-time catch cannot cover, a stale `#tele` window on the pad after REPLAY, and an unguarded audio path inside phase-enter hooks. ## Findings

**1. IMPORTANT — `writeHighscore` silently drops the write when the live backend throws, and its catch comment is false — `src/main.js:150` — CONFIRMED**
The diff changed this line (`storage.set` → `getStorage().set`) but kept the catch `{ /* memory already holds it */ }`. That comment is only true when the memoized impl IS the memory fallback. When the probe succeeded (localStorage impl active — the overwhelmingly common case) and a later `set` throws (quota exceeded, or a private-mode edge where the probe write passes but a real write fails), the catch swallows the error: the high score is lost with no fallback store, no log, and no evidence — against the project's own kee class-6 rule (failures keep their evidence). The memory fallback and the localStorage impl are mutually exclusive memoizations, so there is no path where a write lands in memory after the real backend warmed — the data-loss window is exactly this unlogged throw. Severity tempered by probability (a ~30-byte string against a multi-MB quota), but it sits on a touched line guarding the game's only persistent state. Fix: in the catch, `console.warn('[stage2] highscore write failed:', e && e.message)` (and optionally mirror to an in-memory map); at minimum correct the comment to state the write is abandoned.

**2. ADVISORY — bloom's never-crash catch covers construction only; a render-time failure mode exists that it cannot catch — `src/main.js:489–500, 699, 706` — PLAUSIBLE (failure mode verified in three sources, not induced on hardware)**
I verified in node_modules that three 0.187's `EffectComposer` creates its buffers as `HalfFloatType` (EffectComposer.js:69) and `UnrealBloomPass` creates all five of its internal targets as `HalfFloatType` (UnrealBloomPass.js:105–118). On a WebGL2 context that lacks `EXT_color_buffer_float`, target construction does not throw — but rendering into them produces incomplete-framebuffer warnings and a black/undefined frame every rAF, while `probs.post` keeps reading `'bloom'` and both render sites keep calling `composer.render()`. The construction-time try/catch (which the story's §8.3 argument correctly cites) never engages. Real-world support for that extension is near-universal on WebGL2 hardware, so this is a documented-risk flag, not a predicted failure. What would confirm it: a headed run on a context with the extension force-disabled. Fix: gate composer creation on `renderer.getContext().getExtension('EXT_color_buffer_float')` (fall to the direct-render path when absent), or record the risk in the story file as accepted.

**3. ADVISORY — stale `SPD` text rides the pad phase after REPLAY — `src/main.js:198` + `src/launch.js:305/350` — CONFIRMED (traced writership; visible window 2.6 s)**
`#tele` is only hidden at `enterCountdown` (launch.js:305) and re-shown at `enterAscent` (launch.js:350). On death → REPLAY, `pad.enter` re-shows `#hud`, `#tele.hidden` is still false from the previous stint's ascent, and nothing clears the text — so the previous combat's last `SPD N u/s` sits frozen on the pad for the 2.6 s drift until countdown hides it. This is the same pre-existing stale-telemetry class the story-010 report itself documents ("the cruise telemetry that used to sit frozen in combat") — the story fixed the combat half of the window and changed what the pad half displays, without regressing it. Fix: clear or hide `#tele` in `resetStage()` (one line next to the existing DOM resets at launch.js:216–217).

**4. ADVISORY — `musicTo`/`crossfadeTo` run un-guarded inside phase-enter hooks — `src/audio.js:246–271` called from `src/main.js:158, 169, 180, 199, 206` — CONFIRMED code shape, low probability**
Phase-enter hooks are not wrapped, so an exception inside `makeMusicBag` (e.g., an oscillator-node allocation failure, or the context racing to `closed` between `getC()`'s check and use) would propagate through `setPhase` and abort the phase transition — the exact shape the §8.3 never-crash contract exists to prevent. The audio engine guards its own creation (`ensure()` catches) and every one-shot guards `getC()/muted`; the one uncaught span is the bag-building path. Probability is very low (getC filters closed contexts; WebAudio node creation on a live context essentially never throws in practice). Fix: wrap the `crossfadeTo` body (or just `makeMusicBag`) in try/catch, log once, set `musicBags[name] = null` and continue — the phase lands silent instead of not landing.

**5. NIT — the dying-bag `setVol` before `stop` is dead code — `src/audio.js:251–254` — CONFIRMED**
`dying.setVol(0.0001, 0.9)` (and the 0.6 counterpart) is immediately superseded by `stop()`, which re-ramps the same `out.gain` to the same target with tau `fadeSec/3` (0.933 / 0.6). Harmless; the spec's wording likely suggested it. Fix: drop the `setVol` calls or fold the intent into a comment on `stop`.

**6. NIT — story-008.md contradicts itself on recovery ordering — `production/epics/combat-feel-fix/story-008-bloom.md:23 vs :39` — CONFIRMED**
The design decision says the ladder "restores it [bloom] last"; AC-3 and the shipped code restore bloom BEFORE the DPR climbs. The code matches the AC and the completion notes document the deviation with a one-line swap offered — so this is a story-file edit, not a code change. Fix: amend the design-decision sentence to match the AC and shipped behavior.
