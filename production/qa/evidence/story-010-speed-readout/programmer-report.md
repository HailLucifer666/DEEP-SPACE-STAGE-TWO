## Presentation choice: the `#tele` block

The SPD line lives in `#tele` (right-top telemetry block), written as its full combat content: `SPD 17 u/s` — same label-value-unit grammar as cruise's `DIST/VEL/THR` lines. Why `#tele` and not `#hud-bars`:

1. `#hud-bars` is owned **wholesale** by combat.js's change-gated write (`C.ui.hudBars.innerHTML = bars` rewrites the entire block whenever the bars string changes). SPD content appended there from main.js would be destroyed on the next hull/shield/boost tick. Hosting SPD there without touching combat.js is not possible.
2. `#tele` has **no combat writer at all** today — launch.js writes it only during ascent/coast, so the frozen ascent `DIST/VEL/THR` snapshot sat in the block through the entire fight. main.js taking the block over during combat fills a dead slot instead of fighting another writer.
3. `#tele` is visible on every combat path (ascent unhides it; SKIRMISH never hides it), so no visibility surgery was needed.
4. No template change required: the element, font routing, and `white-space:pre; text-align:right` styling already fit a one-line telemetry readout. The SPD text is dynamic content, not markup.

Cross-phase safety: outside combat the writer never runs (it is only reachable from the combat tick), so the cruise telemetry writer in launch.js keeps working exactly as before. The known pre-existing quirk that stale `#tele` content shows during the 2.6 s pad phase after REPLAY continues to exist — it now shows a stale `SPD x u/s` instead of stale cruise telemetry, same class, not made worse, left alone per the out-of-scope fence.

## The writer (gated-write discipline, TD-009)

Mirrors the two existing patterns exactly: launch.js's tele cadence (0.125 s accumulator — also avoids a per-frame `combatState()` allocation) plus combat.js's change-gated `textContent` write (`if (s !== lastSpd)`). The gate resets to `null` on combat entry so the forced first rewrite always displaces the frozen cruise telemetry left by ascent.

```js
let spdAccum = 0, lastSpd = null;
function tickSpdReadout(dt) {
  if (!ui.tele) return;
  spdAccum += dt;
  if (spdAccum < 0.125) return;
  spdAccum = 0;
  const s = Math.round(COMBAT.combatState().speed);
  if (s !== lastSpd) { ui.tele.textContent = `SPD ${s} u/s`; lastSpd = s; }
}
function tickCombat(dt, t) { // combat core (combat.js) + the SPD line — main owns #tele in this phase
  COMBAT.tickCombat(dt, t);
  tickSpdReadout(dt);
}
```

## Second task — gameover sag VERDICT (Gate A, headed / real GPU)

**Decision: artifact — pinned. The sag does not exist on real hardware; no fix proposed, nothing implemented.**

Headed measurement (RTX 3060, Direct3D11 via ANGLE — GPU string captured in-run), 144 Hz display, 1280x800, `CONSOLE []` in both runs, occlusion/paused samples excluded (0 excluded):

| Phase | avg fps | min | max | n |
|---|---|---|---|---|
| combat | **143.2** | 126 | 144 | 45 |
| gameover | **144.0** | 144 | 144 | 62 |

Delta: gameover vs combat = **-0.6%** (gameover marginally *faster*). Both phases pin at the vsync ceiling; the min 126 in combat is the first two warm-up seconds (shader compile). Against the headless soak's gameover 54 / combat 60, the headed numbers are the pinning evidence: the headless gap is a software-renderer artifact — the gameover card's `backdrop-filter: blur(3px)` over the live scene is disproportionately expensive on CPU rasterization and free on a real GPU.

Measurement method notes (for future soaks — both discovered the hard way):

1. **Occlusion throttling invalidates unattended headed sampling.** A covered Edge window reports `visibilityState: 'hidden'`, rAF stops, and `fps.read` sits at its init value of 60 forever while the sim freezes mid-wave — a run of my probe spent 151 s reading a frozen "60 fps" with hp 100 / wave 1 / 4 enemies unchanged. Fix: `--disable-features=CalculateNativeWinOcclusion --disable-backgrounding-occluded-windows` plus per-sample visibility checks and `Page.bringToFront`.
2. **Natural death is not a reliable gameover gate, headed or not.** Wave 1 RNG can leave a gunner alive whose 12-damage bolts (~6 dps) lose to shield regen (14 dps after 3 clean s) — an idle player then sits at equilibrium forever and wave 2 never unlocks (one 91 s headed run showed exactly this). The deterministic path is the existing probe switch: `?restartProbe=1` forces a death ~0.7 s after combat entry, giving a clean ≥60 s gameover window; the combat baseline is sampled from a separate idle run.
