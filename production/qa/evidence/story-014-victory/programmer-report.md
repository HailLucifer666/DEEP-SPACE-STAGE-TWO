## 1. What was implemented

1. **Victory trigger (the reported design decision)** — handled inside `src/combat.js`'s
   `C.bossApi.report` **wrapper** (combat.js owns the api object; `boss.js` is UNTOUCHED and
   stays a pure signal source, per the story's "signal only" scope):

   ```js
   report: (r) => { C.api.report(r); if (r && r.bossDefeated && !C.dead) C.api.go('victory'); },
   ```

   Why this shape (the wiring warning's ask): the trigger fires **on the report EVENT path** —
   synchronously inside the boss's death-cinematic report call — never as a `lastReport`-slot
   poll. A slot poll lives in phase ticks that stop the moment a teardown lands; if the player
   dies mid-cinematic, combat tears down and the poll would never run. The wrapper cannot be
   orphaned: it IS the event. Two deliberate details:
   - **The report lands FIRST**, then the `go` — the bossProbe drive's death-stage check reads
     `lastReport.bossDefeated` later in the same frame, so probe parity is preserved and the
     story-013 asserts all still hold.
   - **The `!C.dead` guard makes the two card paths mutually exclusive.** The player's death
     clock is 0.7 s real time; the boss cinematic is 1.2 s. If the player is already dead when
     the report lands, gameover wins (the report still lands — probes see it — but no victory
     go). If victory lands first (boss report before the death clock expires), `clearCombat`
     cancels the death clock (C.dead = false) and the death card can never land. Every
     interleaving yields exactly one card; no second latch is needed (the boss reports
     `bossDefeated` exactly once per combat — `startDeath` is latched by `applyDamage`'s
     `B.dying || B.dead` early return and `B.dead` short-circuits `tickBoss`).
2. **`victory` phase (`src/phases.js`)** — mirrors `gameover.enter`'s shape line for line:
   `musicTo('title')` (the same dawn crossfade — new music is out of scope), `game.timeScale = 1`
   (card reads real time; restarts never inherit slow-mo), `writeHighscore(max(score, hs))`,
   card text writes (`SCORE — N` / `TIME — M:SS` via a local `fmtClock` — never a raw float),
   `#hud` hidden, card shown, active-element blur, and a `victoryEntries` counter on
   `window.__stage2` (mirror of `combatEntries` — the exactly-once probe surface). `exit()` hides
   the card (exit-before-enter semantics, same as gameover's). **`PLAYING_PHASES` untouched** —
   victory is a card phase, the cursor returns. No restart-probe hook (the RP drive never
   reaches victory).
3. **Combat clock (`src/combat.js`)** — `C.time` accumulates the scaled `sdt` while alive
   (`if (!C.dead) C.time += dt;` at the top of `tickCombat` — dt is already `dt * timeScale`
   from loop.js, so the death slow-mo slows the world AND the clock, and death freezes it
   exactly), reset `C.time = 0` in `enterCombat` (per-fight — NOT the global `game.time`, which
   launch phases own), surfaced as `time: +C.time.toFixed(2)` in `combatState()`. The card reads
   it; the debug readout and every probe now carry it for free.
4. **`#victory` overlay (`tools/index.template.html`)** — follows the gameover card's DOM/CSS
   pattern exactly: same `.overlay` card, same z-48 backdrop + blur (grouped into the existing
   `#pause,#gameover,#victory` rules), same `.pill` row typography (Orbitron heading / Rajdhani
   lines, added to the existing font-routing lists), with the accent shifted to the **win cyan**
   (`var(--accent)` on the heading + glow) — the death card keeps its gold; a WIN reads the
   brand color, not the death color. Elements: `VICTORY` heading, `#vic-score` (`SCORE — 0`
   seed), `#vic-time` (`TIME — 0:00` seed), one `[ REPLAY LAUNCH ]` pill. **No SKIP** — the
   fight is won, no shortcut past the win. `hidden` by default; joined `OVERLAY_ELMS` (main.js)
   so the story-001 sweep hides it on every phase change; the entering phase re-declares it.
   `index.html` regenerated by `npm run build` only.
5. **Wiring (`src/main.js`)** — ui map gains `victory/vicScore/vicTime/vicReplay`; `ui.victory`
   joins `OVERLAY_ELMS`; `ui.vicReplay` wires `setPhase('pad')` on the same line as the death
   card's REPLAY (identical landing — pad re-seats the rocket via `clearCombat` +
   `LAUNCH.enterPad`); `window.__stage2.probeDamagePlayer(n)` exposed (probe surface for the
   double-fire assert). main.js held at the story-011 composition-root limit: **500/500 lines**
   (the three additions were compacted onto existing lines when dep-check caught 503).
6. **Found-defect fix (in-story, reported)** — the pre-fix pad capture
   (`s14-replay-pad-stale-pip-prefix.png`) shows a **stale edge pip riding the pad** after the
   victory REPLAY. Root cause: the pips are combat's writes (`tickCombat` sets opacity every
   frame) but `clearCombat` reset `#hud-bars`/`#hud-score`/`#tele`/`#warn` without them — and
   the card transitions never run `combat.exit` (exit-before-enter runs the ENTERING phase's
   exit), so the last combat frame's pip state survived into the pad. **Pre-existing on
   master** (verified: master's combat.js never touches pips in `clearCombat` — the death-card
   REPLAY has the same leak); the victory story made it visible in retained evidence. Fix: one
   drain line in `clearCombat` (`for (const pip of C.pips) pip.style.opacity = '0';` — same
   class as the existing HUD clears, inside the §8.6 drain; the death-card path inherits it).
   Regression test: the harness paints every pip ON at the card and asserts the pad drained
   them (deterministic — the natural stale pip depends on raider bearings at the final combat
   frame, which is flaky; the forced-state proxy pins the clearCombat contract exactly).
7. **`tools/victory-shot.mjs` (new, committed evidence tool)** — captures the two retained
   screenshots via CDP off the bossProbe drive (boss-shot.mjs precedent; not in the story's
   file list — flagged, same as story-013's runner).

**Untouched by design**: `src/boss.js` (signal payload only — zero changes), `src/pool.js`,

## 5. Self-review findings / reported judgment calls

1. **Trigger path = bossApi.report wrapper (chosen option)** — no `go` extension on the boss
   api, no boss.js change. The boss stays domain-pure (reports facts); combat.js owns policy
   (what the fact means). The event-path firing satisfies the story-013 wiring warning; the
   slot is still written for probe parity. Reported as required.
2. **Victory vs death race, resolved deliberately**: whichever signal lands first wins, and the
   guard + teardown make it impossible to see both cards. Residual edge (noted, not guarded):
   if the player dies DURING the boss cinematic, the boss's `deathTick` restores
   `timeScale = 1` at cinematic end only if it completes — but the player's death clock (0.7 s)
   always expires before a cinematic that started later (1.2 s), so gameover.enter's
   `timeScale = 1` is what actually restores the scale in that interleaving. No visual gap.
3. **Score on the card is honestly 0 in the probe runs** — the boss kill carries no score
   (story-013's explicit hand-off: "story-014 owns the victory rewards"), and this story's spec
   defines no victory bonus either — the card shows the score earned in the fight. The assert
   pins the FORMAT (`SCORE — N`), not a value, so a future reward change won't fight the harness.
4. **The found-defect pip fix** deviates from the strict four-assert list ("GAINS exactly these
   asserts") — it is the 14th assert + one clearCombat line, in a pre-authorized file, fixing a
   pre-existing master leak that my own retained evidence exposed. The death-card REPLAY
   inherits the fix. Flagged here for the orchestrator's review; reverting mutation 5 and the
   assert is a two-line change if the orchestrator prefers it deferred to a polish story.
5. **main.js hit its 500-line ceiling** — dep-check caught 503; the three additions were
   compacted onto existing lines (comment-preserving merges), landing exactly 500. The next
   story touching main.js will need to extract something rather than add.
6. **The victory phase freezes the combat scene under the card** (enemies/bolts stop ticking,
   pools drain only when the next phase enters — exactly gameover's existing behavior; the
   blur covers it). No behavior change from this story; noted so nobody reads the frozen
   raiders as a victory-path bug.
7. **Entity counts in the evidence screenshots** (51 vs 52 between two pad captures) are
   boot-time derelict seeding variance, not a leak — the restart-probe contract (entities 31
   identical ×3 runs at combat entry) is the allocation gate and is green.
8. **`?bossShot=1` (story-013's evidence variant) is unaffected** — the victory trigger fires
   during that drive too (it goes through the same report wrapper); boss-shot.mjs captures its
   phase shots BEFORE the death stage, so its screenshots are unchanged.
