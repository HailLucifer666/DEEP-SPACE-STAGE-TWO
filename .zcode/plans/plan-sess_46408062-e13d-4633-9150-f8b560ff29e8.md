# Install Claude-Code-Game-Studios into E:\Game Build → tag `good-studio`

## Context

You want the game-studio skill framework (github.com/donchitos/claude-code-game-studios — MIT, 49 agents / 74 skills / hooks / rules / 62 templates, all project-scoped inside `.claude/`) installed and used on this game. It's built as a project template, so installing into an existing project means a **selective, non-destructive copy** — its `src/`, `studio-tests/`, `.github/` and `.git/` must never touch ours.

## Install steps

1. **Clone to an isolated temp dir** (untrusted download → own empty dir): `git clone --depth 1 https://github.com/donchitos/claude-code-game-studios.git build/tmp-gs-clone` — inspect what's actually inside (dir listing shown raw) before copying anything.
2. **Copy into `E:\Game Build`** (selective):
   - `.claude/agents/`, `.claude/skills/`, `.claude/templates/`, `.claude/docs/` — full copy (the framework itself).
   - `.claude/hooks/`, `.claude/rules/`, `.claude/settings.json` — copied as-is, but flagged: these are Claude-Code-specific (Python hooks, deny rules, ask-first mode). Whether they fire in this environment depends on the host reading `.claude/settings.json`; if ignored, they're inert — no harm.
   - `project.yaml` — **adapted**, not copied: name STAGE TWO, engine set to web/custom (this is a vanilla three.js browser game — no Godot/Unity), `modes.rigor: minimal` (solo dev, fast iterations — the framework's own light mode).
   - `CLAUDE.md` — adapted short version: studio pointers + this project's existing hard rules preserved (never hand-edit index.html, smoke after every task, one task at a time).
   - `CHANGELOG.md` stub — the release skills expect one.
   - NOT copied: `src/`, `tests/`, `assets/`, `tools/`, `design/`, `docs/`, `production/`, `prototypes/`, `.github/`, `studio-tests/`, its `.git`.
3. **Delete the temp clone** after the copy.
4. **Prove it works**: list the installed skill folders (raw `ls`); read one skill end-to-end and run its core instruction against the game — `/project-stage-detect` or `/smoke-check` fit (our CDP smoke harness feeds it real evidence). Note honestly: the Skill tool's list is built per session — new skills may only appear by name next session; until then I read the skill files directly and follow them.
5. Commit everything as `studio: install claude-code-game-studios framework (agents, skills, templates; rigor=minimal, engine=web)`, tag `good-studio`, STATE line.

## What could break

- `.claude/settings.json` ask-first/deny rules could change permission behavior if this host honors them — if anything starts blocking, first move is removing that one file (flagged, one-file revert).
- Python hooks are required by the template's commit validation — if this host doesn't run them, nothing breaks; if it does and a hook blocks a routine commit, I'll show the hook output and we decide (disable hooks vs adjust).
- 74 skills is heavy process for a solo 4-hour session — `rigor: minimal` is the framework's answer; anything heavier is opt-in per skill.
- Skill-name collisions with existing skills (e.g., `/code-review`, `/design-review` also exist as your personal skills) — project skills take precedence; your globals stay untouched.
